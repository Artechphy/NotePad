## 1. 使用方法与判定口径

- **基本流 B**：用户正常完成目标的路径；**备用流 A**：从指定步骤分出，说明替代操作、边界或失败后的去向。
- 基本流和备用流使用稳定编号，例如 `UC01-B`、`UC01-A03`；每个备用流单独记录结果，不以基本流通过推定全部分支通过。
- 预期以作业要求和本次已选择的功能方案为主；具体 UI 入口按当前实现核对。标注“现状回归”的项目用于防止已有行为退化，不代表教师另有此项要求。
- 设备测试从应用图标、页面、菜单和系统文件选择器操作；检查导出文件时通过文件管理器或文本阅读器打开。内部函数调用不能代替这一层验收。
- 无法从公开入口稳定触发的故障，安排受控组件/故障注入测试；注明替身、隔离数据库或模拟文档提供器，不能称为真实设备验证。
- 本文没有设置启动耗时、搜索延迟等性能合格线；观察到加载不结束或操作卡住时保留现象，记录实际等待时长，不临时编造指标。

### 共同前提

1. 使用专用测试设备、模拟器或隔离用户空间；仅创建和删除下述测试笔记，不操作个人笔记。
2. 执行记录绑定设备型号、Android 版本、应用构建标识及 APK。当前候选为 `app/build/outputs/apk/debug/app-debug.apk`；实际执行前重新记录文件指纹，避免同名 APK 被覆盖后混用结果。
3. 设备满足实际安装条件。当前 minSdk 为11、targetSdk 为34、compileSdk 为35；早期targetSdk 23属于历史候选。实际设备证据只覆盖API 34。安装受阻先记录环境／兼容性原因，不将其写成后续业务流已失败或已通过。覆盖安装迁移还必须满足同一应用ID、同一签名。
4. 导出主流程使用 API 19 或以上、具有可用系统文档保存工具的设备，输出到专用 `NotePad-验收` 文件夹；旧版本禁用导出单独检查。
5. 修改、删除、剪贴板、导出及升级都可能改变测试数据。执行前明确实例、数据和输出目录；恢复基线只清理本次合成数据。升级测试不得通过卸载旧应用来“准备环境”。

### 时间判据

- 列表显示最近修改时间，格式为 `修改于 yyyy-MM-dd HH:mm`，按设备时区显示；没有有效值时为“时间未知”。
- 实际修改标题、正文或分类应更新修改时间；单纯查看、搜索、无改动保存和导出不应额外更新时间。创建时间保持不变。
- UI 仅显示到分钟：同一分钟内修改后显示相同，不单独据此判失败；显示相同也不能证明底层时间没有变化。需要区分时，安排跨分钟操作，或引用精确时间字段的组件断言。不得为制造证据任意调整测试设备时间。
- 默认按修改时间从新到旧，同时间以 ID 降序稳定排列；精确同时间样本和 ID 顺序由受控组件测试补充，不要求普通用户读取内部 ID。
