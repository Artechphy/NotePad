## 4. 缺陷 D01：复制粘贴未带入笔记内容

**优先级：P2。状态：已观察，未修复。影响：UC06-B 不通过。**

复现步骤：

1. 列表定位“周会纪要”，确认原正文为“讨论版本发布。”、分类工作。
2. 长按该笔记，点“复制”。
3. 打开列表“更多”，确认粘贴入口可用，点“粘贴”。
4. 新编辑页实际显示标题/正文的空输入提示，分类为未分类。

预期：新笔记带入原记录的标题、正文及工作分类，后续可独立保存和修改。

实际：内容没有带入。此时存在空新草稿；通过编辑页返回后已清理，没有将它写成一条成功副本。原记录内容可在随后 UC05 的修改前副本中核对。

日志在同一操作时段记录 NotePad 被拒绝剪贴板访问，原因是 `application is not in focus`。结合 `NoteEditor.onCreate()` 尾部直接调用 `pasteNote()` 的代码，故障与新窗口获得焦点前读取剪贴板的时机一致。后续可将读取延后到获焦点，或在仍有焦点的原页面取得必要数据后传递；修复时需保留真实 API 34 回归，不能仅用剪贴板替身证明修复。

本轮按冻结候选执行，未修改业务代码、未绕开此失败、未降低字段断言。修复后至少复测 UC06-B，并检查新建/返回清理及相应受影响测试。

## 5. 环境、驱动问题与处理历史

- 既有 API 37.2 镜像此前无法稳定启动；本轮经指定代理下载并校验官方 Android 14 AOSP ARM 镜像，两个全新实例均可用。未读取或重置用户原有 AVD 数据。
- 首次启动出现旧 targetSdk 的系统提示：[实际画面](00-legacy-target-warning.png)。关闭后应用可操作；这不是新版 Android 安装全面兼容的证明。
- 首次列表自动弹出搜索键盘，遮住右下角入口；系统返回键可收起。操作记录中保留该现象，未修改候选界面。[初始状态](01-empty-list.png)、[收起后](02-empty-list-keyboard-closed.png)。
- 控制器连接半关闭、返回键注入、按文字误中同名搜索框、转场中的移动坐标、系统选择器同一资源 ID 被文件行与文件名输入框复用等，曾导致驱动错误或等待超时。修正均限于测试工具：采用系统输入指令、稳定的节点/类型选择，关闭隔离设备动画后继续。预期输入和业务断言保持。
- 这些驱动失败保存在原始 [results.jsonl](results.jsonl)、`failure-*`/`timeout-*` 文件中，未删除；汇总按 M01 与 UCxx-B 的有效流程结果列出。`copy-basic` 的失败则已确认是产品行为，单列 UC06-B FAIL。
- 导出文件实际从系统文件管理器进入设备自带 HTMLViewer。没有使用自建阅读器或内存输出流替代本轮文件链路。

完整公开 UI 快照及动作在 [ui-actions.jsonl](ui-actions.jsonl)，系统输入、启动和重启操作在 [device-commands.jsonl](device-commands.jsonl)。工具源代码位于 [tools/device-test](../../../tools/device-test/README.md)。
