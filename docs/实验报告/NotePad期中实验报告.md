# NotePad 记事本应用扩展实验报告

本实验在教师指定的NotePad应用上完成列表时间戳、标题与正文查询，并增加界面美化、笔记分类和文本导出。当前版本保留Java和XML界面，以SQLite及ContentProvider管理笔记。全量56项本地测试及相关Android 14设备复测通过，已修复复制粘贴和保存失败后的输入恢复问题；未覆盖分支与人工验收另行保留。

## 一 实验目标与环境

### 实验要求和完成范围

题目要求阅读原有NotePad源码，实现两项必做功能，并根据实际情况增加至少两项功能。本实验选择界面美化和笔记分类，同时实现单篇文本导出。

| 类型 | 题目要求或选定扩展 | 实现结果 |
| --- | --- | --- |
| 必做 | 列表时间戳 | 显示最近修改时间，支持未知值提示 |
| 必做 | 按标题或内容查询 | 参数化子串匹配，可与分类组合 |
| 附加 | 界面美化 | 简洁列表、正文摘要、统一编辑页和状态提示 |
| 附加 | 笔记分类 | 四个固定分类，可保存、筛选和继承 |
| 附加 | 导出笔记 | 由系统保存界面写出单篇UTF-8文本 |

## 二 程序结构与数据设计

### 主要模块

列表和编辑页通过ContentResolver访问NotePadProvider，Provider统一读写SQLite。列表由CursorLoader在后台查询，收到数据变更通知后，按当前关键词和分类刷新结果。

| 模块 | 主要职责 |
| --- | --- |
| NotesList | 列表绑定、时间展示、查询、分类及新建入口 |
| NoteEditor | 标题与正文编辑、保存、撤销、删除、粘贴和恢复 |
| NotePadProvider | 建表、版本升级、CRUD、时间维护与通知 |
| NoteSearch和NoteTimestamp | 绑定查询参数、转义字符及格式化时间 |
| NoteCategory和NoteText | 分类映射、标题生成与摘要处理 |
| NoteExport和NoteExportTask | 导出内容、建议文件名、后台写入及结果反馈 |

### 数据表和升级

数据库文件为应用私有目录中的 `databases/note_pad.db`，笔记表为 `notes`。创建和修改时间均存储为Unix毫秒值，界面显示时再转换为设备时区。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| _id | INTEGER PRIMARY KEY | 记录标识 |
| title | TEXT | 笔记标题 |
| note | TEXT | 笔记正文 |
| created | INTEGER | 创建时间 |
| modified | INTEGER | 最近修改时间 |
| category | TEXT NOT NULL | 分类ID，默认uncategorized |

分类功能使数据库从版本2升级到版本3，采用增量加列：

```sql
ALTER TABLE notes ADD COLUMN category
TEXT NOT NULL DEFAULT 'uncategorized';
```

升级保留原有ID、标题、正文和时间，旧笔记归入未分类。对未知旧版本明确报错，不通过删表重建掩盖兼容问题。隔离数据库测试与真实旧APK覆盖安装分别验证了字段保留和设备安装链路。

## 三 两项必做功能实现

### 列表时间戳

在列表投影和条目布局中加入修改时间，显示格式为 `修改于 yyyy-MM-dd HH:mm`。时间为空、0或负值时显示“时间未知”。列表按修改时间降序排列，同一时间以ID降序稳定排序。

Provider比较标题、正文和分类是否实际变化，再决定是否更新修改时间。纯查看、无改动保存、搜索和已保存笔记导出不会额外改写时间，创建时间保持不变。

### 标题与正文查询

同一关键词匹配标题或正文；分类条件作用于整个OR表达式。使用selectionArgs绑定参数，对百分号、下划线和转义字符作字面匹配。空白关键词恢复当前分类内全部笔记，清空查询仍保留分类。

## 四 附加功能实现

界面采用白底、蓝色操作和清楚的文字层级。列表呈现标题、两行摘要、时间、分类及结果数量；编辑页整合标题、分类和正文，提供保存反馈及删除确认。列表长按删除仍直接生效，与编辑页存在交互差异。

每篇笔记使用未分类、学习、生活、工作中的一个分类，存储稳定ID。分类可与查询组合，在分类中创建新笔记会继承当前分类；修改后重开或重启，分类仍保留。

文本导出先保存当前编辑，再打开系统文件保存界面。后台写出UTF-8文本，包含标题、分类、修改时间和正文。路径字符会从建议文件名中清理，取消选择器不回滚此前保存；写入和关闭成功后才报告成功。该功能不包含导入恢复或云同步。

## 五 保存失败处理与输入恢复

初次设备验收发现，来源不可读时，返回按钮直接关闭页面，暂停阶段的保存虽失败，未保存输入却没有恢复入口。针对该问题先增加四项回归测试，在旧实现上四项均失败。

修复后，完成和返回共用保存判断，失败时留在编辑页并显示状态。系统返回也进入同一逻辑。后台保存失败会提示；标题、正文、分类及保存状态另存到实例状态中，来源暂不可读或已删除时仍可重建编辑页。

失败后可明确选择“更多 → 另存为新笔记”，或在依赖恢复后重试原记录。测试仅受控移除一条预设来源，核对页面返回、系统返回、旋转、后台及保留实例状态后的进程重建；其余五条笔记的字段和时间保持不变。

[[FIGURES|../acceptance/2026-11-14-save-recovery-fix/UC02-A08-return-guarded.png|图5 返回保存失败时输入仍留在编辑页|../acceptance/2026-11-14-save-recovery-fix/process-recovery-saved.png|图6 进程恢复内容另存后重开]]

进程恢复测试先切到后台触发生命周期保存，再受控终止该应用进程，从最近任务打开并确认PID变化。此结果验证了系统保留实例状态后的恢复条件，没有使用清数据或强制停止后重建空任务的方式。

### 完整演示主线

1. 新建学习分类笔记，完成后重开核对三字段。
2. 在学习分类搜索关键词，核对结果数量。
3. 修改标题、正文和分类，确认移出原筛选结果。
4. 切换分类并清空关键词，核对组合筛选。
5. 经系统选择器导出，由文件管理器和阅读器打开。
6. 保存后重启应用，确认数据保留。
7. 确认删除临时笔记，重启后不存在，导出文件仍可读取。

修复候选的七步均已通过。独立升级实例另在真实v2旧应用中准备两条笔记，同签名覆盖安装后，ID、标题、正文、创建和修改时间逐项不变，分类默认及修改后重启持久化也通过。

## 七 结果分析与后续工作

本实验完成了两项必做和三项附加功能，并保留笔记的原有数据入口。时间维护集中到Provider后，无改动查看不会改变排序；参数绑定及括号组合使标题、正文和分类查询保持一致。数据库以增量升级保留旧字段，真实覆盖安装补足了仅靠组件测试无法证明的安装链路。

设备检查暴露了本地测试之外的时序与生命周期问题。复制粘贴需要在窗口获得焦点后读取剪贴板；返回页面不能把一次保存尝试视为保存成功。修复通过保留失败见证、明确失败反馈、保存输入状态和提供另存入口形成回归闭环。

### 尚未覆盖的范围

当前Lint仍有37项警告。十项特殊备用分支尚未补齐，涉及列表读取异常、缺少保存工具、低版本导出、写入或关闭失败、空URI与写入期间重建、删除失败、签名不一致、未知旧版本完整设备链路及升级中断恢复等条件。其他系统版本、实体真机和人工验收也未完成。

后续应根据实际交付设备补必要分支，取得人工操作反馈，再完成最终交付。当前结论为已实现功能及本轮修复范围通过验证，不宣称全部环境和所有分支均通过。
