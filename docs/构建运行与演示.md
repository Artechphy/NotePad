## 构建和本地验证

在工程目录执行。本机JDK及SDK路径如下，其他机器应替换安装位置。不提交 `local.properties`、私钥或凭据。

```bash
env JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
  ANDROID_HOME=/Users/artechphy/Library/Android/sdk \
  bash ./gradlew --offline --no-daemon \
  :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --console=plain
```

`--offline` 只适用于已缓存依赖。首次准备时去掉该选项，从配置的官方仓库获取依赖；本机使用系统TUN路由，不设置HTTP／SOCKS显式代理。旧 `127.0.0.1:65533` 已停用，不复制历史参数。

macOS/Linux可用 `bash ./gradlew`；Windows使用 `gradlew.bat` 并设置对应环境路径。任务也可分开执行：

```bash
bash ./gradlew --offline :app:assembleDebug
bash ./gradlew --offline :app:testDebugUnitTest
bash ./gradlew --offline :app:lintDebug
```

## 安装与保留数据

先查看并明确选择自己的设备：

```bash
adb devices -l
adb -s <设备序列号> install -r docs/acceptance/2026-11-14-save-recovery-fix/artifacts/candidate.apk
adb -s <设备序列号> shell am start -a android.intent.action.MAIN \
  -c android.intent.category.LAUNCHER -n com.example.android.notepad/.NotesList
```

`<设备序列号>` 需替换。覆盖安装保留数据还要求相同应用ID和签名，不能先卸载后声称升级保留数据通过。已在独立合成样本上验证v2→v3升级。

自动化会新建、删除、操作剪贴板和导出文件，必须按[设备测试说明](../tools/device-test/README.md)使用专用实例，不能指向个人笔记库。

## 七步演示

固定样本及精确断言见[测试与验收流程](测试与验收流程.md)。

1. 新建学习分类笔记，标题“验收临时笔记”、正文“安卓验收正文”，完成并重开。
2. 在学习分类搜索“安卓”，观察结果数、摘要与时间。
3. 修改标题、正文和分类为工作，返回后移出原筛选结果。
4. 切换工作分类，保留再清空关键词，观察组合筛选。
5. 从编辑页导出，通过真实系统保存界面写文件，再由文件管理器／阅读器打开。
6. 保存后重启，重开确认三字段仍在。
7. 从编辑页确认删除临时笔记，重启后查无记录；导出文件仍可打开。

正常演示不需要制造数据库故障。保存失败、进程终止和旧版升级是专用合成实例中的技术验收场景。

## 常见问题

- JDK路径无效：本机旧 `JAVA_HOME` 曾指向不存在版本，使用上方命令的临时覆盖方式，不必修改全局配置。
- 离线缺依赖：确认网络和仓库可用，去掉 `--offline` 准备依赖，不能将未执行写成通过。
- 安装异常：记录系统、APK指纹和实际输出；当前只验证API 34，不以绕过限制外推兼容性。
- 保存提示失败：留在编辑页重试，或使用“更多 → 另存为新笔记”保留当前输入。
